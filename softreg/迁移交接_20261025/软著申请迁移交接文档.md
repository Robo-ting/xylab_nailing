## 5 软件总体结构和三条业务链

这是一个研究和流程演示软件，工程名为 XYLab，登记名按第二节统一。前端使用 React 18、TypeScript、Vite 5、Zustand、HashRouter 和 Canvas 2D。后端是 FastAPI；Qwen 是另一个独立 HTTP 服务。

```text
浏览器 5173
  ├─ 链 A 预设板件与 mock 缺陷 → 浏览器几何与规划 → 规则动作 → JSON/CSV
  ├─ 链 B 图片/视频/摄像头 → /api → FastAPI 8000
  │                            → 固定演示缺陷框 → 多边形筛选 → 像素网格钉位
  └─ 链 C 长板建档与站位 → 照片上传 → 演示标注图
                               ├─ 规则分等 / 红外桩
                               └─ QWEN_VL_URL → Qwen 8011 → 文字建议或辅助分等

机器人页和二维动画展示状态，不向实体机械臂发运动命令。
```

### 5.1 链 A 浏览器端样例规划

入口是 `F/src/pages/Dashboard.tsx` 和 `Planning.tsx`，共同调用 `F/src/lib/pipeline.ts` 的 `runPipeline`。状态和初始数据在 `F/src/store/useSystemStore.ts`、`F/src/mock/boards.ts`、`defects.ts`、`rules.ts`。

处理顺序为：建立板面栅格 → 依据 ROI 过滤并栅格化缺陷 → 圆形核膨胀 → 可选软代价场 → 标记装配重合区外单元 → 收集可行点 → KD-tree 最近邻或软代价寻优 → 缺陷规则动作 → 结果和日志。

| 文件，均相对 F/src/lib | 作用 |
|---|---|
| `geometry.ts` | 点在多边形、几何相交、距离、重心等 |
| `grid.ts` | 板面栅格、缺陷与 ROI 处理、重合区外禁用 |
| `morphology.ts` | 圆形核膨胀和核心／缓冲区分类 |
| `kdtree.ts` | 二维最近可行点查询 |
| `costmap.ts` | 软代价场与候选点目标函数 |
| `decision.ts` | 确定性规则和缺陷矩阵，给出动作及理由 |
| `pipeline.ts` | 串联上述步骤，输出钉位、决策、统计和日志 |
| `ec5.ts` | 独立的 Eurocode 5 参数计算器代码 |
| `types.ts` | 点、缺陷、钉位、日志、动作等数据结构 |

动作枚举以代码为准：`NAIL`、`PREDRILL_THEN_NAIL`、`RELOCATE`、`SKIP`。早期文案中的 `PREDRILL` 只是简写，不宜直接当接口枚举。

该链中几何和规划确实由代码计算；样例板件位置、缺陷和手眼参数不是真实标定输入。`decision.ts` 的 `stage: 'llm'`、固定置信度和条款标签，也不证明实际调用了大模型或检索库。`pipeline.ts` 中日志 `compliant` 实际按“动作不是 SKIP”赋值，**不能解释为通过完整工程规范验算**。`ec5.ts` 没有被 `runPipeline` 自动调用为统一合规检查。

### 5.2 链 B 图像源和像素规划

主要入口仍在 `Planning.tsx`；前端通信在 `F/src/api/client.ts`。后端链路是：

`B/api/routes_sources.py` → `B/sources/registry.py` 获取帧 → `B/inference/detector.py` 生成演示框 → `B/planning/zone_filter.py` 筛选框 → `B/planning/planner.py` 生成像素网格点。

支持的代码通道包括图片上传与替换、视频上传、本地摄像头编号、暂停／恢复、快照／流、保存／清除多边形区、执行一次检测和规划。工业相机现场联调并未由这些接口本身证明。

当前 `get_detector()` 返回 `DemoFixedDetector`。它以 1024×768 参考图的两个死节框为模板，按输入宽高缩放，不分析照片中真实缺陷。健康检查返回 `detection_mode: demo_fixed`。

像素规划只针对 `dead_knot` 框外扩避让，按边距和间距铺网格；它不是链 A 的 KD-tree 算法。`/api/plan` 默认可限制在固定演示可钉矩形；图像源的 `/run` 使用整帧规划。多边形区在当前实现中主要筛选缺陷框，**并不等价于把全部候选钉位限制在该多边形里**。

图像源、帧和多边形会话由进程内对象管理，没有可迁移的数据库。程序重启后不要继续使用旧 `source_id`，应重新创建输入源。

### 5.3 链 C 长板站位 Qwen 与分等

入口：`F/src/pages/Intake.tsx`；通信：`F/src/api/intake.ts`；后端入口：`B/api/routes_intake.py`。

1. 创建长板，设置板长与站位；前端按设定间距对站位吸附。
2. 逐站位上传照片，`intake/vision.py` 调用同一个演示检测器。
3. `intake/annotate.py` 绘制标注图，保存到 `B/uploads/intake`。
4. 请求钉位建议时，`intake/advisor.py` 把标注图编码为 Base64，并附提示词，发送给 Qwen 服务。
5. Qwen 的 `/analyze` 返回 `{"text": "..."}`，由界面展示。该文字不直接变成机械臂运动命令，也不自动改写链 A 的最终规划结果。
6. 分等请求：有标注图时，当前路由使用 `visual_grade` 调用 Qwen；没有图或模型失败时回退 `rule_grade`。应检查响应中的 `grader` 和 `ai_error`，区分 `qwen` 与 `rule`。
7. 红外通道未配置设备 URL 时使用 `StubInfrared`；开启模拟时在板长 40% 处生成桩缺陷。没有真实探伤设备联调证据。

`B/intake/grade_standard.py` 保存分等提示词和解析；即使输出带“GB/T 4817”或等级文字，也不自动成为经验证的标准分级结论。当前分等流程取第一张可用标注图，不能描述为已完成全部照片融合评估。

`B/intake/session.py` 明确只把长板、站位、红外和等级放在内存中。保存的标注 JPG 不包含完整会话恢复能力；迁移前若要保留现场，需另存板件／站位 JSON、结果和原图，并标明对应关系。

### 5.4 坐标和字段约定

| 所在链路 | 坐标／数据约定 | 易出错处 |
|---|---|---|
| 浏览器样例规划 | 板件平面坐标，参数按 mm 表示 | 不是实际相机标定后的精度证明 |
| 后端图像源 | 像素坐标；框为 `[x1,y1,x2,y2]` | 不能与 mm 直接相加或比较 |
| 前端缺陷对象 | 框为 `[x,y,w,h]`，并生成矩形 polygon | 转换在 `api/client.ts`，不是实例分割掩码 |
| 类型名称 | 后端 `dead_knot`，前端 `knot_dead` | 通信层需要映射 |
| 长板站位 | `x_mm`、`length_mm` 等是 mm；照片框仍是像素 | `advisor.py` 使用“整板长度线性对应照片宽度”的近似，不是手眼标定 |
| 操作结果 | 决策理由、条款标签、置信度、分等文字 | 输出字段存在，不代表相关算法或工程验证完成 |

### 10.2 国家登记材料

本项目的 11 页核定稿用于填报准备，内容目的不同，不能直接认为已经完成软件文档鉴别材料。也不能把“文档常见交 60 页”误解为必须扩写一本 60 页手册。
